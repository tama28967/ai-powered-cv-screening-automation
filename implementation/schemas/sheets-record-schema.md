## Job Opening sheet (added 2026-08-09; now referenced by `job_open_id`, still not consumed for scoring)

A second sheet, `Job Opening`, exists in the same spreadsheet (`PRJ-0001 — Applicant Records`). The Founder populated it directly with real columns beyond the original request: `job_open_id`, `job_name` (renamed 2026-08-09, was `nama_job`), `minimal_score`, `skill`, `minimal_pengalaman_kerja`, `start_job_opening`, `end_job_opening`, `interview_date`, `status` (`OPEN`/`CLOSED`), `overide_status`, `interview_quota`, `count_applicant_record`. A third sheet, `Job List`, holds a simpler reference catalog (`job_name` (renamed 2026-08-09, was `nama_job`), `minimal_score`, `skill`, `minimal_pengalaman_kerja`) without dates/status — presumed the source job openings are cloned from when a new dated posting opens, not yet confirmed.

**Now referenced:** the applicant's chosen `job_open_id` (Founder-added dropdown, ADR-0026) is captured at intake and stored on every Applicant Record — see `record_id` and `job_open_id` above.

**Still not wired into scoring.** `minimal_score` / `minimal_pengalaman_kerja` / `skill` gating the AI evaluation's recommendation against the specific job applied for is a business rule not yet requested — the evaluation prompt remains generic, unchanged. Out of scope for this round; flagged for a future decision, not invented.

**Known limitation — Form Trigger's dropdown is static.** n8n's Form Trigger field options are fixed at design time, not fetched live from the `Job Opening` sheet. The dropdown currently lists the two `status: OPEN` postings as of 2026-08-09 (`Front End Developer_2026-08-01`, `Project Management_2026-08-01`). **Whoever changes a job opening's status must manually update the Form Trigger's field options to match** — there is no automatic sync. The `Webhook Intake` path has no such limitation (it accepts whatever `Lowongan`/`job_open_id` value the caller sends) since it's meant for an external platform that can source the live list itself.

## Evaluation criteria now sourced per-job (2026-08-13, Founder-directed)

The AI Agent's scoring prompt previously used a generic 0-100 relevance rubric with no job-specific bar. It now reads `minimal_score`, `skill`, and `minimal_pengalaman_kerja` off the applicant's matched row in the **Job Opening** sheet (resolved once, in `Resolve job_open_id`) and states them as explicit minimum requirements in the prompt — `recommendation: "shortlist"` is only appropriate when the candidate meets that job's bar, not a generic score. The separate **Criteria Config** sheet (structural-only, blocked on Open Technical Question 1) remains unused — Job Opening was chosen because it already holds real, Founder-populated values per posting.

## Human review gate removed, quota check added (2026-08-13, Founder-directed)

**W2 (`PRJ-0001 — W2 Human Review Gate and Notification`) is deleted.** Its notification logic is absorbed directly into W1: immediately after AI scoring, W1 reads a live count of already-`accepted` records for the same `job_open_id` and compares it against that job's `interview_quota` (both from Job Opening). Outcome: AI rejects → `rejected`; AI shortlists and quota still has room → `accepted`; AI shortlists but quota is full → `rejected_quota_full` (canned message, not the AI's reason). The record is written and the outcome email sent in the same execution — no manual HR approval step remains. HR's role is now interviewing already-accepted candidates, not gating notification. This is a genuine scope change against the Blueprint §SS4 commitment that originally required a human gate — executed on explicit, chat-confirmed Founder direction, not inferred.

**Duplicate detection and file-size validation moved earlier.** Both now run immediately after job resolution, before any Drive upload / PDF extraction / Gemini call — a duplicate or oversized (>2MB) submission gets an immediate direct webhook response and no wasted processing cost. File-size enforcement is new: the previous "Validate File Type and Size" node only ever checked MIME type despite its name: size was never actually enforced.

## System Config sheet (added 2026-08-13, configurable output language)

A third sheet, `System Config`, holds operational switches — currently one row: `config_key=active_language`, `config_value=en|id`, `notes`. This is a **global** switch (applies to every candidate until the Founder edits it), not per-candidate. It controls the language of every system-output surface: webhook responses, error messages, candidate emails, and the AI's `reason` text — CV intake itself stays language-agnostic (Gemini reads any language natively, no config needed for that direction). Full translated text lives in the W1 workflow itself, not in this sheet — the sheet only selects which language is active. See `deployment/test-runtime-bindings.md`'s 2026-08-13 entry for the full design and live verification (both `en` and `id` proven end-to-end, including a real Gmail send in each language).
